# Session meetings

Each saved session now has a Join meeting action and a copyable session link. Participants must sign in to a workspace account. The same account can join from multiple tabs, browsers, or devices at once; each connection appears separately with the name entered before joining (default: Anonymous). Display names are self-chosen labels, not verified identities; signing in is still required. To test browser chat, sign in on two browsers, open the same session link, enter different names, click Join meeting in both, and open the chat panel. All accounts in the current team workspace can join its sessions; guest links are not supported.

The client lazily loads LiveKit's conferencing UI. Audio and video start disabled; participants can enable devices, share their screen, chat, and leave. Typed chat and microphone speech have separate capture controls. Speech capture temporarily records available microphone tracks in the capturing browser and sends complete audio parts to Gemini for transcription. Video is excluded; audio is not stored on the application server. Both chat and speech transcripts can be explicitly saved as sources through the existing PostgreSQL session API. Gemini can draft reports from saved transcripts; Qwen can generate cited workflow suggestions. Full recording storage and live AI interviewing remain subsequent work.

`POST /api/meetings/token` checks origin, authenticated session, and existence of the saved team session. Tokens expire after five minutes and grant only the named room, without administration privileges. The token remains only in component memory. Each token issuance creates a participant identity using an account hash and a random connection ID, so another join by the same account does not replace the earlier connection. Logout does not remotely evict an already-connected second tab; leave the call before signing out. Full call revocation would require server room management and is not implemented.

Configure protected CI variables `LIVEKIT_URL` (public `wss://...`), `LIVEKIT_API_KEY`, and masked/hidden `LIVEKIT_API_SECRET`. These are server-only variables; no API secret is sent to the browser. With configuration absent, join returns a useful unavailable message and saved-source workflows continue working.

Logout uses configured `APP_ORIGIN` for its redirect, rather than the container's internal request host or untrusted forwarded headers. Set `APP_ORIGIN=https://<your-public-origin>` in production.

## Chat capture → saved evidence → review

1. Join the meeting and open its chat panel. Choose one browser to capture the conversation; captures from multiple browsers are separate sources.
2. Tell participants that chat will be saved in the shared team workspace and obtain their agreement. Check the agreement box, then click **Start chat capture**. This is an operator attestation, not individual electronic consent. It does not automatically notify other browsers.
3. New text messages received by the capturing browser are retained with attendee labels and sender-provided UTC timestamps. Earlier chat, messages sent while capture is stopped, attachments, and audio/video are excluded. Names and times are not verified identities or server-attested timestamps. Streamed message updates replace the current draft text rather than duplicating paragraphs.
4. Click **Stop chat capture**, then **Save chat as source**. This writes an immutable transcript source into the existing session in PostgreSQL, using the same authentication, origin checks, size limits, revision checks, and source-preservation rules as imported transcripts. No database migration is required.
5. Open **Session review → AI-assisted review**, select the meeting chat source, and analyze. With Gemini configured, choose **Draft meeting report with Gemini** to generate a saved report and download its Markdown draft. Suggestions remain unconfirmed until reviewed. Continue through questions and the recommendation in **Next steps**.

The draft stays available after leaving the meeting or a failed save, while this page remains open. It is not saved automatically. Save or download a chat backup before navigating or reloading; the backup can be imported through the transcript form. A save conflict retains the draft but requires reloading the latest session before retrying. At the 50,000-character source limit, capture stops visibly; save the current part and start another capture. Messages rejected by the limit are not included. Disconnects stop capture; rejoining requires explicitly starting it again.

## Microphone speech → saved transcript → review

1. Configure `GEMINI_API_KEY` and an audio-capable `GEMINI_MODEL`, even if review uses Qwen. No database migration is required. Run the server in a region where the Gemini API is available (this deployment uses Cloud Run in us-central1); `GEMINI_BASE_URL` and `GEMINI_GATEWAY_KEY` are only needed for an optional authenticated relay. Unsupported models fail visibly and retain the audio draft.
2. Join, enable a microphone, and designate one capturing browser. Tell every participant that microphone audio will be sent to Google Gemini and the resulting transcript saved in the team workspace. Check the speech agreement box. This is the capturing operator's attestation, not individually collected electronic consent or an automatic room announcement.
3. Click **Start speech capture**. The browser records separate complete audio containers for available, unmuted local and subscribed remote microphone tracks. It does not request another microphone, capture video, or capture earlier speech. Tracks that join or unmute during capture are added; muting or disconnecting ends their current audio part. Audio from unavailable/unsubscribed tracks and periods between separate captures is excluded.
4. Click **Stop speech capture**; capture also stops after two minutes or on leaving/disconnect. Complete audio parts are transcribed, including the final recorder data. The UI shows pending transcription and keeps saving disabled until every part completes. Times are browser part-start timestamps, not word timings; attendee names are labels, not verified identities. Silence may produce no transcript. This is batch transcription, not live captions.
5. Review the speech preview against your notes, then **Save speech as source**. The immutable source is labeled as an AI transcript, with names and part-start timestamps. It uses existing session revision checks and source limits. Open Session review to analyze it with Gemini or Qwen.

Failed transcription keeps the affected audio in browser memory for **Retry transcription** or **Download audio backup**. Successful transcription releases the associated audio. Failed saves keep the text draft and offer a transcript download. Nothing is saved automatically; navigation/reload loses unsaved text and audio despite the browser unload warning. Audio is sent inline to Gemini (maximum 4 MB per part), with no application file storage. The transcription endpoint checks origin, sign-in, team session existence, explicit agreement, supported MIME type, canonical base64 and request size. Provider errors are redacted and requests time out. No remote recording permissions or LiveKit egress service are needed.
